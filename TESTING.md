## TC-01 — интерфейс

- Требование: R3 
- Предусловия и данные: Режим normal. Имя: `Тест`, Email: `test@example.com`, Тема: `JavaScript и DOM`.
- Шаги:
  1. Открыть главную страницу.
  2. Заполнить поля формы указанными данными.
  3. Нажать кнопку «Отправить заявку».
  4. Найти новую карточку в списке справа и проверить бейдж с темой.
- Ожидаемый результат:В карточке отображается тема «JavaScript и DOM», счетчик заявок увеличивается на 1.
- Факт, версия и статус запуска: Версия `workshop-1.0`, режим `normal`. В карточке отображается тема HTML и CSS (подмена значения). Статус: **Fail** (см. BUG-01).

## TC-02 — API

- Требование: R7 (Успешный POST создаёт запись, последующие GET возвращают её), R8 (Все обязательные поля).
- Предусловия и данные: Режим normal, сброс стенда выполнен (3 заявки). API-лаборатория.
- Метод, путь и тело запроса: `POST /applications`, тело: `{"name": "Петр", "email": "petr@example.com", "topic": "api"}`.
- Шаги:
  1. Отправить POST запрос с указанным телом.
  2. Получить ответ (201 Created, id=5).
  3. Отправить GET `/applications/5` — проверить наличие полей.
  4. Отправить GET `/applications` — проверить наличие записи в общем списке.
- Ожидаемый статус, поля ответа и состояние после запроса: POST возвращает 201. GET по id и GET списка содержат объект с id=5 и полем `topic: "api"`.
- Факт, версия и статус запуска: Версия `workshop-1.0`. POST вернул 201 (id=5). GET `/applications/5` вернул объект. Но GET `/applications` **не содержит** заявку с id=5 (баг сервера, см. CH-09). Также `GET /applications/3` не содержит поле `email`. Статус: **Fail**.

## BUG-01

- Заголовок: Неверное отображение темы «JavaScript и DOM» в карточке заявки.
- Требование: R3 (Тема `javascript` означает «JavaScript и DOM»).
- Версия/режим/окружение: workshop-1.0, normal, Chrome 129.
- Предусловия и точные данные: Имя `Тест`, email `test@example.com`, тема `javascript`.
- Шаги воспроизведения:
  1. Заполнить форму указанными данными.
  2. Нажать «Отправить заявку».
  3. Посмотреть на новую карточку в списке «Заявки».
- Ожидаемый результат: Бейдж темы в карточке содержит текст «JavaScript и DOM».
- Фактический результат: Бейдж содержит текст «HTML и CSS».
- Свидетельство: [Вставь сюда скриншот карточки]
- Влияние на пользователя: Пользователь видит, что его записали не на ту тему, которую он выбрал. Вводит в заблуждение.
- Предложенный приоритет и обоснование: Высокий. Искажает пользовательские данные на экране.
- Гипотеза причины, если есть: В файле `script.js` в объекте `topicLabels` для ключа `javascript` указано значение `'HTML и CSS'` вместо `'JavaScript и DOM'`.

## BUG-02

- Заголовок: Заявка с темой `api` исчезает из списка после успешного создания.
- Требование: R7 (последующие GET списка возвращают созданную запись).
- Версия/режим/окружение: workshop-1.0, normal, API-лаборатория.
- Предусловия и точные данные: POST `/applications`, `{"name": "Петр", "email": "petr@example.com", "topic": "api"}`.
- Шаги воспроизведения:
  1. Отправить POST запрос.
  2. Получить 201 и id.
  3. Отправить GET `/applications`.
- Ожидаемый результат: В списке есть заявка с новым id.
- Фактический результат: В списке нет этой заявки (при этом GET по конкретному id её находит).
- Свидетельство: (Прикрепи JSON из кнопки «Скачать запрос и ответ»).
- Влияние на пользователя: Пользователь оставляет заявку, видит успех, но в списке участников её нет.
- Гипотеза причины: В файле `server.mjs` в функции `createApplication` стоит условие `if (application.topic !== 'api') database.applications.push(application);`, из-за чего заявки с темой `api` не попадают в базу (массив).

## BUG-03

- Заголовок: Отсутствует поле email в ответе API для заявки id=3.
- Требование: R8 (все обязательные поля в ответе по id).
- Версия/режим/окружение: workshop-1.0, normal, API-лаборатория.
- Предусловия и данные: Сброс стенда выполнен. Запрос: GET /applications/3.
- Шаги воспроизведения:
  1. Открыть API-лабораторию
  2. Выбрать GET, ввести путь /applications/3
  3. Нажать «Отправить»
- Ожидаемый результат: Статус 200, объект содержит id, name, email, topic, createdAt.
- Фактический результат: Статус 200, но поле email отсутствует.
- Свидетельство: JSON ответа без email (см. лог API-лаборатории)
- Влияние на пользователя: Клиенты не могут получить контактные данные, интеграции могут ломаться.
- Предложенный приоритет: Средний (нарушение контракта R8).
- Гипотеза причины: В server.mjs в findApplication стоит `if (id === '3') delete result.email;`.
